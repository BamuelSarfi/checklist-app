# design-sync notes — checklist-kitchen-ds

## Decisions

- **Font substitute accepted (user OK'd 2026-08-29)**: `'Myriad Pro'` is referenced by the original kitchen-app CSS but is an Adobe commercial font never actually shipped as a web font in production — the app has always silently fallen back to the browser's default sans-serif. The synced design system renders with the same system-sans-serif substitute; this is not a fidelity loss, it matches real production behavior.
- **16 components, not 11**: `Card`'s compositional sub-parts (`CardHeader`, `CardTitle`, `CardDescription`, `CardArrow`, `CardBadge`) are separately exported from `src/components/Card/Card.tsx` and get picked up as their own top-level components by the converter's PascalCase-export discovery, in addition to the 11 originally scoped components. They're legitimate standalone-renderable pieces (no provider/context dependency), so previews were authored for all 16 rather than excluding the 5 via `componentSrcMap`.

## Known render warns

- **`[RENDER_THIN]` on `components/general/Modal/Modal.html`** (all 3 stories: Success, ErrorState, Info) — the generic validate check and the stacked multi-row review sheet both show the modal box cropped (top portion, including part of the message, missing). Root-caused by hand: the review harness wraps each single-mode story in `<div class="ds-single" style="transform:translateZ(0)">`; per the CSS spec, any transform on an ancestor becomes the containing block for `position:fixed` descendants (Modal's `.ds-modal-overlay` uses `position:fixed; inset:0`). Since `.ds-single` has no other content and fixed children don't contribute to flow height, it collapses to ~0 height, so the overlay's "centered" position collapses toward that point and the box overflows upward off-screen. Confirmed via an isolated `?story=Success` screenshot at the declared 420x300 viewport — same artifact, so it's not a stacking-only issue, it's the `transform:translateZ(0)` specifically. This is a review-harness rendering quirk, not a Modal defect — a real page mounting Modal (including, expected, Claude Design's actual rendering) won't wrap it in a transformed zero-height ancestor. Graded `good` on all 3 cells (content/colors/structure verified correct); this warn is expected on every future re-sync and should NOT be treated as new.

- **StatusBadge emoji glyphs render as empty boxes in this repo's headless capture sandbox** (`components/general/StatusBadge/`, all 4 states) — the sandbox used to run `package-validate.mjs`/`package-capture.mjs` here has no color-emoji font installed (no root/sudo access to install one — see [[playwright_sandbox_setup]] memory for the broader Chromium-in-this-sandbox situation). The component's default labels use literal emoji characters (`"🟢 Synced"` etc.) which is fine, real-world content — virtually every actual browser/OS renders these correctly. Graded `good` on all 4 cells since colors/layout/text are otherwise correct; expected to keep showing empty boxes on any re-sync run from this same sandbox unless a color-emoji font gets installed.

## Re-sync risks

- The design-system package's own tokens (`src/tokens/tokens.css`) are hand-kept in sync with the live app's `src/views/style.css` `:root` block — there's no automated link between them. If the app's tokens change, this package's tokens (and therefore this synced design system) will silently drift until someone updates both by hand.
- `cssEntry` is pinned to `dist/index.esm.css` because the converter's auto-scrape didn't find it from the JS entry alone (esbuild's ESM output doesn't reference its sibling CSS file via an import statement the scraper could follow). If the build's CSS output filename ever changes, `cssEntry` needs updating too, or a future sync will silently regress to `[CSS_RUNTIME]` (self-styling fallback, losing all real styling).
